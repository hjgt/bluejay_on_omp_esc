# OMP 原厂 BLHeli_S 16.7 固件反汇编报告

分析日期：2026-09-15

本报告记录对用户通过 C2 从目标电调读取的 `orig.hex` 的只读分析。原厂
镜像不收入本仓库；报告只保留可复核的哈希、地址和硬件结论。

## 1. 镜像完整性与身份

| 项目 | 结果 |
|---|---|
| Intel HEX | 记录校验和、EOF均有效 |
| 覆盖范围 | 完整 `0x0000～0x3FFF`，共16384字节 |
| 非 `FF` 字节 | 5724 |
| 最高非 `FF` 地址 | `0x1DF5` |
| `0x2000～0x3FFF` | 全部为 `FF` |
| SHA-256 | `f4dfe722c0b07da2e552387c5a98b31fa326bd29c115e1b46e6a1bbbbee62291` |
| 布局标签 | `#A_L_15#`，位于 `0x1A40` |
| MCU标签 | `#BLHELI$EFM8B10#`，位于 `0x1A50` |
| BLHeli_S版本 | 16.7 |
| Bootloader文本 | `BLHeli471d` |

用户报告独立读取的第二份文件与该文件一致。这个结果说明目标未启用阻止
用户程序区读取的代码保护，也说明现在已经有可恢复原厂主 Flash 的备份。
它不包含 BB2 高地址独立非易失区，因此不应称为整颗芯片的所有非易失数据
镜像。

## 2. 与官方16.7的关系

原厂设置和身份区 `0x1A00～0x1BFF` 与官方
`A_L_15_REV16_7.HEX` 完全一致，但主程序不是官方 A 布局成品。直接逐地址
比较会出现2703字节差异，原因主要是自定义引脚宏改变了指令长度，继而使
大量跳转目标地址发生平移。

对 `0x0000～0x19FF` 做插入/删除感知的字节序列对齐后，约95.1%的字节可与
官方 A_L_15 对齐；例如 `0x0076～0x090C` 连续2199字节完全一致。差异集中在
中断跳转地址、换相引脚宏、关断函数和端口初始化。这说明它非常接近：

> BLHeli_S 16.7 公共控制逻辑 + 厂商自定义硬件布局文件 + 沿用的 A_L_15 标签。

所以不能按标签把它当成官方 A 布局，但可以可靠地用 BLHeli_S 16.7 源码给
反汇编命名和还原语义。

## 3. MCU和时钟路径

复位向量为：

```text
0x0000  LJMP 0x19FD
0x19FD  LJMP 0x0D33
```

Timer0的 `0x000B` 向量不存在，而其余BLHeli_S中断向量与24 MHz的 L 路径
一致。初始化在 `0x0D48` 写 `CLKSEL=0x00`，身份与Bootloader签名也是BB1。

因此原厂程序是按 **EFM8B10/L/24.5 MHz兼容路径** 编译的，尽管板上实际
芯片是 EFM8BB21。BB21能运行这套兼容指令和SFR子集。Bluejay移植仍应按
实际硅片选 **H/BB21**；其运行中会使用约48 MHz，因此所有以时间为单位的
参数必须按Bluejay定义换算，不能照抄机器周期数。

## 4. 端口初始化：六路门极和信号脚

复位初始化的关键指令：

```text
0x0D4D  P0      = 0x20
0x0D50  P0MDIN  = 0xFF
0x0D53  P0MDOUT = 0x8F
0x0D59  P0SKIP  = 0x00
0x0D5C  P1      = 0x00
0x0D5F  P1MDIN  = 0x01
0x0D62  P1MDOUT = 0x01
0x0D68  P1SKIP  = 0x00
0x0D6B  P2MDOUT = 0x00
0x0D6E  XBR2    = 0x40
0x0D71  XBR1    = 0x02
```

`P0MDOUT=0x8F` 表示 P0.0、P0.1、P0.2、P0.3、P0.7 是推挽输出；
`P1MDOUT=0x01` 表示 P1.0 是推挽输出。结合换相代码中的逐位置位/清零，
得到以下确定映射：

| 逻辑相 | FD6288 | MCU |
|---|---|---|
| A | HIN1 / LIN1 | P0.0 / P0.1 |
| B | HIN2 / LIN2 | P0.2 / P0.3 |
| C | HIN3 / LIN3 | P0.7 / P1.0 |

`P0=0x20` 和多处对 P0.5 的读取表明 P0.5 空闲时释放为高。程序先在
`0x0DBD` 写 `IT01CF=0x05` 将 INT0 接到 P0.5，检测数字协议后又在
`0x0E50` 写 `IT01CF=0xD5`，把正反边沿分别交给 INT0/INT1。因此 **P0.5
就是原厂程序的控制信号输入**。

P2.0/C2D在原厂程序中保持非推挽。移植布局也让它保持高阻并从Crossbar
跳过，减少运行中的C2D总线争用。

## 5. P1.3和三相反馈的决定性证据

程序启用的是比较器1：

```text
0x0DED  CMP1CN0 = 0x80
0x0DF0  CMP1MD  = 0x00
```

换相代码只向 `CMP1MX` 写入三种值：

| CMP1MX | 负输入 CMXN | 正输入 CMXP | 含义 |
|---:|---|---|---|
| `0x43` | P1.4 | P1.3 | 相A与公共参考比较 |
| `0x53` | P1.5 | P1.3 | 相B与公共参考比较 |
| `0x63` | P1.6 | P1.3 | 相C与公共参考比较 |

这直接确认：

- P1.4、P1.5、P1.6依次是逻辑 A、B、C 的BEMF反馈；
- P1.3是三相共用的过零比较参考；
- 比较器没有使用输出反相选项，Bluejay应保持 `COMPARATOR_INVERT=0`。

这里的“公共参考”不等于“物理三相星点”。结合在路测得的三个独立
约10k/0.94k相位分压，P1.3到A/B/C均约13.9k很可能是经公共地和分压网络
测出的间接路径。最符合现有证据的模型是：P1.3提供与相位采样同比例的
半母线阈值，而不是由三只电阻直接汇合三相得到的物理虚拟中性点。

## 6. 六步换相表

正常方向的程序行为还原如下：

| 换相 | 固定导通低边 | 互补PWM相 | 浮空检测相 |
|---|---|---|---|
| 1→2 | A / LIN1 / P0.1 | C / HIN3+LIN3 | B / P1.5 |
| 2→3 | A / LIN1 / P0.1 | B / HIN2+LIN2 | C / P1.6 |
| 3→4 | C / LIN3 / P1.0 | B / HIN2+LIN2 | A / P1.4 |
| 4→5 | C / LIN3 / P1.0 | A / HIN1+LIN1 | B / P1.5 |
| 5→6 | B / LIN2 / P0.3 | A / HIN1+LIN1 | C / P1.6 |
| 6→1 | B / LIN2 / P0.3 | C / HIN3+LIN3 | A / P1.4 |

反向分支使用完全相反的换相顺序。原厂程序的 CEX0/CEX1 路由值分别是
P0SKIP `0x00`、`0x03`、`0x7F`；Bluejay X布局使用更严格的
`0xFC/0xFF`、`0xF3/0xFF`、`0x7F/0xFE`，但两者选中的前两个未跳过
引脚相同，最终仍分别落到三组HIN/LIN。

## 7. 死区的机器码证据

原厂布局标签中的 `15` 不是伪装出来的孤立字符串。PWM更新代码在
`0x04CA` 明确执行：

```text
SUBB A,#0x0F
```

这就是 `FETON_DELAY=15`。BLHeli_S/Bluejay把一个单位定义为约20.4 ns，
所以目标非重叠时间约为：

```text
15 × 20.4 ns ≈ 306 ns
```

原先的 `X_H_5` 只给约102 ns，与原厂已验证值不一致。移植目标因此改为
`X_H_15_24`。最终仍必须在限流条件下观察FD6288的HO/LO或上下管Vgs，
确认任何时刻同一桥臂都没有交叠导通。

## 8. 对 Bluejay X布局的结论

反汇编确认以下设置正确：

```text
A: P0.0/P0.1，反馈P1.4
B: P0.2/P0.3，反馈P1.5
C: P0.7/P1.0，反馈P1.6
信号: P0.5
比较参考: P1.3
比较器: CMP1，非反相
死区: 15（约306ns）
PWM: 首测24kHz
MCU目标: H / EFM8BB21
```

反汇编消除了引脚和逻辑相位的不确定性，但不能代替功率级波形验收。首次
刷写后仍需完成：C2逐字节回读、静态电流、三桥臂HIN/LIN与HO/LO无重叠、
拆桨低速启动以及全目标电压/负载/温升测试。
